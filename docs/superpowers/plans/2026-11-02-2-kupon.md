# Kupon Uygulama Planı

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Esnaf gerçek indirim tanımlasın; müşteri kuponu alıp randevuda ya da kasada kullansın.

**Architecture:** `coupons` tanımı, `coupon_claims` müşteriye özel kodu tutar. Bütün yazmalar RPC üzerinden yapılır. Randevuya bağlı kuponun kullanılmışlığı saklanmaz, randevudan hesaplanır; böylece iptal ve gelmeme ek iş gerektirmez.

**Tech Stack:** Postgres/Supabase (test: PGlite), Next.js 16, Expo SDK 57.

**Spec:** `docs/superpowers/specs/2026-11-02-kupon-gecikme-vitrin-design.md` (bölüm 2)

**Önkoşul:** `2026-11-02-1-gecikme-haberi.md` (`migration-check.mjs` oradan gelir).

## Global Constraints

- `schema.sql` tek kaynaktır; yeni tablolar `drop table` listesine eklenir. Ek dosya: `supabase/migrations/20261105_kupon.sql`.
- Paket özelliği adı `coupons`; `esnaf` ve `pro` paketlerine eklenir, `baslangic` paketine eklenmez.
- Haftanın günleri `working_hours` ile aynıdır: 1 = Pazartesi, 7 = Pazar. Saatler işletmenin `timezone` değerine göredir.
- Yüzde 1–90; kupon süresi en çok 90 gün; kod 6 haneli sayı; kasada 10 dakikada 20 yanlış deneme; geri alma 10 dakika.
- Türler web ve mobilde aynı tutulur. Yeni yerel mobil paket yok, QR okutma yok.
- Dal: `kupon`. Canlı SQL ve yayın kullanıcı onayı ister.

## Review Focus

- Sınırı 1 kalan kupona aynı anda iki müşteri: yalnızca biri alır. Task 1 testi (satır kilidi, sıralı çağrı ile sınır denetimi).
- Randevuya bağlı kodun kasada da girilmesi: reddedilir, indirim iki kez uygulanamaz. Task 1 testi.
- Esnaf kuponu durdurunca kuponu önceden alan müşteri: kodu bitiş tarihine kadar çalışır. Task 1 testi.
- Hesabını silen müşterinin kuponu: rapor sayısı değişmez, kod kullanılamaz. Task 1 testi.
- Eski uygulama sürümünden kuponsuz randevu: `book_appointment` eskisi gibi çalışır. Task 2 testi.

### Task 1: Kupon veritabanı

**Files:**

**Interfaces:**
- Produces:

  - `coupon_claims`: `id, coupon_id, business_id, customer_id (on delete set null), code text, redeemed_at timestamptz, appointment_id (on delete set null), created_at`; `unique (coupon_id, customer_id)`, `unique (business_id, code)`

  - `redeem_coupon_code(p_business_id uuid, p_code text) returns uuid`, `undo_coupon_redeem(p_claim_id uuid) returns void`

  - `business_coupons(p_business_id uuid) returns table (...)` (kupon alanları + `claimed`, `used`)
  - `coupon_valid_at(c coupons, p_at timestamptz) returns boolean`, `coupon_price(p_price numeric, p_type text, p_value numeric) returns numeric`, `coupon_claim_used(c coupon_claims) returns boolean`
