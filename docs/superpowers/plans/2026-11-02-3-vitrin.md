# Vitrin Uygulama Planı

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lokanta, market gibi randevusuz esnaf menü ve kuponla sayfa açabilsin.

**Architecture:** `businesses.business_type` sayfa, panel ve kuralları ayırır. Menü `menu_items` tablosunda durur. Yorumlar kullanılmış kupona bağlanır. Randevulu işletmenin akışı değişmez.

**Tech Stack:** Postgres/Supabase (test: PGlite), Next.js 16, Expo SDK 57.

**Spec:** `docs/superpowers/specs/2026-11-02-kupon-gecikme-vitrin-design.md` (bölüm 3)

**Önkoşul:** `2026-11-02-2-kupon.md`.

## Global Constraints

- `schema.sql` tek kaynaktır; ek dosya `supabase/migrations/20261106_vitrin.sql`.
- Paket: `vitrin`, 149 ₺, `staff_limit` 1, özellikler `{coupons,announcement,links,menu}`; deneme 2 ay.
- İşletme başına en fazla 200 ürün.
- Yeni kategoriler (kimlik, etiket): `lokanta` Lokanta, `kafe` Kafe, `firin` Fırın & Pastane, `market` Market, `manav-kasap` Manav & Kasap, `magaza` Mağaza. Web ve mobil listesi aynı anda.
- Mevcut randevulu işletmede hiçbir ekran değişmez. Vitrin esnafı randevu ile ilgili ekran görmez. Çalışma saatleri kalır.
- Yeni yerel mobil paket yok. Dal: `vitrin`. Canlı SQL ve yayın kullanıcı onayı ister.

## Review Focus

- Vitrin esnafının doğrudan adresle `/panel/hizmetler`e girmesi: panele yönlendirilir. Task 3.
- Eski APK'dan vitrin sayfasına randevu isteği: sunucu reddeder, anlaşılır mesaj verir. Task 1 testi.
- Yönetici randevulu işletmeyi vitrine çevirirken yaklaşan randevu: reddedilir. Task 1 testi.
- Yorumsuz, menüsüz yeni vitrin sayfası: boş başlıklar görünmez. Task 4.
- Rezerve sayfa adlarıyla çakışma ve mevcut sayfa önbelleği: menü değişince sayfa bayat kalmaz (menü ve kuponlar istemciden okunur). Task 4.
